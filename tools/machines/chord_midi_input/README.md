# ChordKeys external MIDI candidate

Private test v7 adds external-keyboard note ownership to the fixed full-feature and no-filter/P/O/N profiles. Enable Keys on a CHORD track and use the normal track MIDI channel or auto channel. Hold an external note and press T1–T6 to retrigger its harmony at the original velocity. Releasing a pad keeps the current harmony; releasing the keyboard note ends it. A held pad also prepares the next external note.

Live recording uses the normal note producer, UI notification consumer and recorder, capturing HARMONY at the chosen step. Step Recorder gets a separate HARMONY snapshot after its note setters, since those bypass the live recorder. In Step Recorder, each harmony retrigger ends the prior note and records the new harmony at the next step. Grid recording retains the existing hold-step-TRIG + harmony-pad workflow.

The dispatcher hooks are at `0x40081a1e` and `0x400816ca`, after native channel/track routing. Velocity-zero uses the existing note-off dispatcher. The native per-track reset drops captured ownership. The pad hook retains the physical TRIG path, grid editing, and the existing no-note live-lock fallback. The Step Recorder hook replaces only its call at `0x467ada9e`. Sources link into the reserved Model-TG last MiB at `0x467b0800`; the tail copy count is extended. The shared display mask remains untouched.

Local build and proof: `output/firmware/build_chord_midi_input_v7.py`, `prove_chord_midi_input_v7.py`, and `prove_harmony_preview_v5.py`. The proof runs the final image after its native bootstrap; it executes MIDI dispatch, native audio/recorder event construction, the UI notification consumer, live recording, Step Recorder, and pattern save/load. Clock positions and peripheral output are controlled by the fixture. USB/DIN transport, concurrent hardware scheduling, and physical audio still require hardware verification.

Main 2.07 serves the corrected v4 full-feature image without this experimental MIDI change. Candidate filenames contain `chordkeys-midi-input-test-v7`.

Private test v9 fixes the sequencer helper ABI: the fourth native argument at 400551a6 and 40055bfa is a step index, not a note. Both sequence paths and TRIG preview now read that step's stored note (or track base note) before the native builder can be interrupted. This prevents a temporary step number from being latched as a slice note and used for its varispeed pitch correction. The old mismatch and acceleration reproduce in `prove_slice_step_abi_v9.py`; all six tracks, 64 steps, base-note fallback, native selector and speed compensation agree in v9. `prove_slice_recorded_steps_v9.py` additionally creates real live-recorded notes and manual grid notes through native setters before comparing the three paths.

In MIDI Out, holding LFO and turning an assigned knob starts a gesture: the first event assigns its CC as destination; subsequent events on that same knob adjust signed LFO depth. Release LFO, change knob/track/page or change the CC to start a fresh assignment. OFF knobs do nothing. Unheld gray knobs remain CC controls; the LFO menu is edited with DATA only. `prove_midi_lfo_menu_v9.py` verifies both pages, positive/negative depth changes, release/reset and unchanged CC values.

V9 retains physical global-filter removal and P/O/N in the no-filter profile. Hardware verification of the new Slice/quick-depth changes is pending. Public main stays on the approved 2.07 image until the new candidate is confirmed.


Private test v10 addresses the remaining hardware report that v9 Slice playback stays pitched up. V9's ABI test checked the pre-builder note and injected a matching voice pitch; it did not prove ownership after the asynchronous audio queue. The renderer consumes one shared live-note byte per track, so queued step playback can use another UI note for slice latching and varispeed compensation. `mi_slice_audio` now publishes the accepted audio event's actual note, only for Sample Wizard, after native locks and before rendering. Native sequencer and lock-only hooks still call their original MIDI/Chord delegate exactly once. No UI getter, allocation or MIDI/file operation is added to the audio interrupt.

`output/firmware/prove_slice_queued_pcm_v10.py` runs the native audio queue, voice pitch update and sampler PCM renderer. V9 reproduces higher/lower rates and different PCM from preview when the shared table holds a prior/future note. Both v10 profiles compare all 64 PCM values and window/rate with preview across six tracks, three notes, forward/reverse trims and two PITCH settings. `prove_slice_audio_guard_v10.py` checks all 18 machines, note-on/off, lock-only and invalid note cases and preserves the original callback arguments/return. The DATA-only MIDI LFO menu and assign-then-depth gesture are unchanged. The user confirmed v10 fixes Slice playback on hardware on 21 October 2026.
