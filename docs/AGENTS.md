# AGENTS.md — docs/

The GitHub Pages site, served from `main`: <https://18nelli18.github.io/Modded-Cycles/>. Static files, no build step,
no framework. Read the root [`AGENTS.md`](../AGENTS.md) first.

```
index.html             home page (intro, mods, "what's new" from release.js)
flasher/index.html     the web flasher page
flasher/app.js         its UI: texts (en/fr), FEAT cards, GUIDE_OF, REF_MAINOS (generated block), flashing steps
flasher/builder.js     builds the .syx in the browser (port of tools/build.py + mtlib)
flasher/flasher.js     .syx checks, Web MIDI sending: classic (CONFIG › UPGRADE) and fast (Transfer protocol, notes/37)
flasher/tweaks.js      GENERATED by tools/gen_flasher_tweaks.py — never edit by hand
guide/index.html       the user guide, one numbered <section id="…"> per mod
assets/release.js      MC_RELEASES: flasher versions, newest first
assets/site.js, site.css, guide.css, cycles.js   shared behaviour and styles (language, theme)
```

## Two languages, everywhere

Every visible text exists in English and French. In HTML: `<span data-l="en">…</span><span data-l="fr">…</span>`; in
`app.js`: the `en` and `fr` objects (same keys); in `release.js`: `{ en: "…", fr: "…" }`. The page picks the
language from the browser and remembers the EN/FR switch. French addresses the reader as « vous » on the site.
Write for musicians: what changes on the machine, which buttons to press, the limits; no addresses.

## Adding a mod to the flasher

1. Add it to `FEATURES` in `tools/gen_flasher_tweaks.py` (`"status": "experimental"`, `credit`, `excludes`,
   `includes` or `needs` if any), then `python3 tools/gen_flasher_tweaks.py` to regenerate `flasher/tweaks.js`.
2. `python3 tools/ref_mainos.py --cycles … --syntakt …` rewrites `REF_MAINOS` in `flasher/app.js`: the flasher refuses
   to send a build whose MAIN OS hash is not listed, so every offered combination must be there.
3. In `flasher/app.js`: the card texts in `FEAT.en` and `FEAT.fr` (`label`, `desc`, optional `note` shown once
   ticked), and the guide anchor in `GUIDE_OF`.
4. In `tools/webflash_smoke.js`: the expected order of tweaks and cards, their tags, and a check that the French card
   and its guide link render.
5. A guide section in `guide/index.html` (next number, before *Samples OS*; renumber the ones after): a lede, the
   steps (`<ol>`) with the buttons in `<b>`, then `<dl class="facts">` with the limits and a *Tested* / *Experimental*
   line saying how it was checked. Copy the `#tempo` or `#trig-hold` section.
6. A new entry at the top of `assets/release.js`: next version (`1.25` is the last; `1.22` to `1.24` are taken by other
   branches), today's date, 2 to 4 changes (what the user gets, the limits, how it was checked, which mods it goes
   with). Once merged into `main`, the English text is posted as is to the Discord server's #announcements
   (`.github/workflows/discord.yml`), so write it for musicians.
7. Bump the version stamp: the same `YYYY-MM-DD-NN` string in `window.MC_BUILD` (`flasher/index.html`) and every
   `?v=` of the three pages (`index.html`, `flasher/index.html`, `guide/index.html`). A stale stamp makes browsers mix a
   new page with cached old scripts.

The home page list (`ol.mods` in `index.html`, each item with the controls it lights in `data-hl` and the screen
text in `data-lcd`) is a short selection, not every mod: add an item only when the mod is a headline one, and ask.

When Maxime has tested it: `status` to `"tested"` in `FEATURES` (regenerate `tweaks.js`), the guide's *Tested* line,
the release entry ("Tested on a Model:Cycles"), and the stamp again.

## Checks

```sh
python3 tools/gen_flasher_tweaks.py --check
tools/webbuild_check.sh        # builder.js == tools/build.py, byte for byte
tools/webflash_check.sh        # flasher.js validates .syx like tools/mtlib/syx.py
tools/webflash_smoke.sh [model-cycles_OS1.13.syx Syntakt_OS1.42.syx]   # the page in jsdom; with the real files,
                                                                         # every combination vs REF_MAINOS
```

`builder.js` and `tools/build.py` must stay equivalent: a change to how one reads a tweak goes into the other in the
same commit. The flasher only offers tweaks that keep the OS update over USB working; `6ch-multiout`,
`sdvintage-snare` and `sdvintage-exact` stay command-line only.

The page must keep working from `file://` and under GitHub Pages: no `fetch` of local files (that is why `tweaks.js`
embeds the JSON), scripts loaded with relative paths. Users' files never leave the browser.
