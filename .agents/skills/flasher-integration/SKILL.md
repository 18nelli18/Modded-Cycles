# Web flasher integration

The page builds the firmware in the browser from the user's own `.syx` and sends it over Web MIDI. Static files,
no build step, must work from `file://` and on GitHub Pages; users' files never leave the browser.

```
docs/flasher/app.js      UI: FEAT texts en/fr, GUIDE_OF, REF_MAINOS + REF_MODS (generated blocks), flashing steps
docs/flasher/builder.js  port of tools/build.py + mtlib (must stay byte-identical)
docs/flasher/flasher.js  .syx checks, Web MIDI (classic CONFIG › UPGRADE, fast Transfer protocol, notes/37)
docs/flasher/tweaks.js   GENERATED by tools/gen_flasher_tweaks.py; never edit by hand
```

## Adding a card (in this order)

1. `FEATURES` in `tools/gen_flasher_tweaks.py` (French `label`/`desc`, the comments above `CATS` define every
   key): `id`, `cat` (one of `pack sound seq live screen io`), `"status": "experimental"`, `credit` (`None` or
   `{"kind", "who", "repo"}`), `license` when it carries outside code, `variants: [{"file": "OO-<id>", "label":
   None}]`, and rules if any: `excludes` (cannot be ticked together), `includes` (tweaks already inside it),
   `requires` (add-on to another card; same `with` keys as that card, and each tweak JSON `requires` the matching
   tweak), `with` (variant file when another family is ticked), `joins` (MACRO/ACID with the engines).
   The position in `FEATURES` is the build order (`REF_MAINOS` keys); the page sorts by `cat` for display.
2. `python3 tools/gen_flasher_tweaks.py` → `docs/flasher/tweaks.js`; then `--check`.
3. `python3 tools/check_overlaps.py`.
4. `python3 tools/ref_mainos.py --cycles firmware/model-cycles_OS1.13.syx --syntakt firmware/Syntakt_OS1.42.syx`
   rewrites `REF_MODS` (hash of each tweak's writes `w` and payload `p`) and `REF_MAINOS` (MAIN OS of each card
   alone, every pair, the largest sets) in `app.js`. Never edit those blocks or resolve merge conflicts in them by
   hand: rerun the script after merging. A new kind of rule between cards goes into both `app.js` and
   `ref_mainos.py`.
5. `docs/flasher/app.js`:
   - `FEAT.en["<id>"]` and `FEAT.fr["<id>"]` (same keys): `label`; `short` (~80 chars, what it does on the machine
     plus any deal-breaker); `desc` (Details drawer); optional `note` (shown when ticked), `clash` (why it does
     not go with an excluded mod), `parts` (packs), `"eng-<code>"` shorts (engine cards).
   - `GUIDE_OF["<id>"] = "<guide section id>"`.
6. `tools/webflash_smoke.js`: the expected tweak order (`ids.slice(0, N)` list), the expected **display** order of
   rows (`feats.join()`, by section), a check that the French row and its guide link render.
7. Run `tools/webflash_smoke.sh` (synthetic), then with the real files (sample of `REF_MAINOS`, each mod checked).

Texts follow the `bilingual-user-docs` skill (musicians, buttons, limits, no addresses; French « vous »).

## Status change after a hardware test

`"status": "tested"` in `FEATURES`, regenerate `tweaks.js`, then the guide's *Tested* line, a release entry, and the
stamp (skill `hardware-test-handoff`).

## Invariants

- `builder.js` ≡ `tools/build.py`: a change to how one reads a tweak goes into the other in the same commit
  (`tools/webbuild_check.sh`). `flasher.js` validates `.syx` like `tools/mtlib/syx.py` (`tools/webflash_check.sh`).
- Only tweaks that keep `CONFIG › UPGRADE` over USB working are offered; `6ch-multiout`, `sdvintage-snare`,
  `sdvintage-exact` stay command-line only.
- No `fetch` of local files (that is why `tweaks.js` embeds the JSON); relative script paths.
- Bump the `?v=` / `MC_BUILD` stamp whenever a page or script changes (skill `bilingual-user-docs`).
- The home page list (`ol.mods` in `docs/index.html`) is a short selection: add an item only if Maxime asks.
